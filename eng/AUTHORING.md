# Engineering: A Very Short Introduction · 导读：页面编写规范

公共部分见 `~/tutorials-deploy/AUTHORING-COMMON.md`，动笔前两份都要完整读。下面只写这本书的参数和差异；两份有出入时以这一份为准。

## 这本书和它的读者

*Engineering: A Very Short Introduction*（David Blockley 著，Oxford University Press 2012，牛津「通识读本」丛书）。Blockley 是布里斯托大学的土木工程荣休教授，研究结构安全、风险和系统思维。正文约 3.6 万词：Preface 和 6 章。第 1 章讲工程是什么，后五章按他自己划的五个「时代」（重力、热、电磁、信息、系统）讲工程的历史和原理。书末有 Glossary、References、Further reading。

读者：中文母语的程序员，好奇，**读书为了乐趣**。**读英文 Kindle 电子书**，没有译本，长按能查单词。读者说四样都会卡：

- **机制和概念**：力和功、共振、热机和熵、电磁感应和交流电、晶体管和二进制、系统和风险，光读文字建立不起直觉。每页「先用中文过一遍」汇总成 `terms.html`；全书几个模拟器，先猜再跑。
- **英文**：工程行话、熟词生义（work、power、charge、stress、field）、英式说法。每页词条，「记下」接跨书词本。
- **人物、项目和历史背景**：书里点名的工程师、科学家、发明和工程。每页「书里的人和项目」，配照片。
- **今天怎么看**：书 2012 年出版。每页「今天怎么看」「本站怎么看」，**别让书把读者带歪**。

**提前知道内容没有坏处**：没有分界线，「这一页在做什么」可以直接说主旨。只有模拟器（「先猜：……」）让读者先想。

### 读者手上这本书的样子（写指路之前必须知道）

- **原书章内没有小标题**，一章一口气写下来。节是本站按段号分的，编号 `§k`，节名是本站起的。`assets/chapters.js` 的 `EG_SECS`：`p` 段号范围，`w` 词数，`en` 这一节第一段开头几个词（读者在 Kindle 里搜它），`t` 本站节名，`tier` 档，`line` 这一节起什么作用。这些由 `eg.js` 显示，**你不用抄**。
- **读者看不到段号，Kindle 也没有和纸书对得上的页码。** 页面上指路用 `§k` 加本站节名，或者原文里连续 4–7 个词（`.loc`、`.at` 里的 `en`），读者拿去 Kindle 里搜，所以**一字不差**（破折号照抄，斜体的 `*` 不抄）；**选不含引号的 4–7 个词**（lint 不收带引号的定位）。段号只写在 `data-p` 里。
- 原书有 20 张图（`{F}` 图注行，图的描述在 `source/FIGS.md`）和第 1 章的 Box 1。正文常说「（Figure 8）」：页面提到原书的图时写「原书图 8（卡诺循环）」，读者在 Kindle 里翻得到。
- 书末 Glossary 35 条（`source/text/glossary.txt`）：概念块可以对照它，**释义不能照抄**。References（`source/text/refs.txt`）按章列出处，有几条是作者的补充说明；页面写「书里没给出处」之前先查它。

## 写作依据

- 原书 `source/text/NN.txt`：`# NN 章名`，每行一段 `[段号] 文字`。`{Q}` 缩进的引文（多是他引别人的话）、`{B}` 方框、`{F}` 图注（不编段号，`[img N]` 是图的文件名）。`*词*` 斜体；上标写作 `^`（`10^(20)`），下标写作 `_`（`T_1`）。Preface 在 `00.txt`，由主编在 00 页讲，作者页不引它。
- **先完整读你这几节的原文，再读底稿（阅读包里你这一页的那几节）和 `source/LINE.md`**（概念分工、术语表、各页提示），图的描述读 `source/FIGS.md` 里你这几节的图。底稿写进页面之前回原文核对，对不上的以原文为准，在报告里说。
- 阅读包：`sh tools/pack.sh <页id>` 把要读的切好，在一条消息里并行 Read 全部。

## 页面骨架

骨架照样板页抄。页头、顶栏、页末导航、备案号页脚、「全书六章」带子、分节地图的节名和开头、词条的「记下」、笔记的保存，都由 `eg.js` 注入。各节顺序固定：

1. `这一页在做什么`：`<div class="gist">`，不超过 200 个汉字：这一章讲哪个问题、主旨是什么、好玩在哪。不按原书顺序复述。紧跟一张图（照片或 SVG）。
2. `读之前：这一页在全书的哪里`：第一行 `<div class="linehere"></div>`；一段话（不超过 200 个汉字）说前面讲到哪、这一章接着往哪走；可选 `<div class="heads-up">`（**别被带歪**，不超过 120 个汉字，一页至多一个：书里有个说法今天的证据或教科书不站在作者那边，或者只拿比喻撑着，直接说方向）；`<div class="crux">` 一个问题；`<ol class="qs">` 2–4 个带着读的问题，每个后面标 `<span class="sec">§k</span>`。
3. `分节地图`：`<ol class="secmap">`，每节一条 `<li data-sec="k"><span class="what">…</span></li>`，一条不少，只写 `.what`（不超过 90 个汉字：这一节干什么、读的时候留意什么）。超过 1000 词的节，用一处 `<span class="at" data-p="段号">原文开头 4–7 个词</span>` 点出节里的转折，读者在 Kindle 里搜得到。（`.at` 两用：内容以 `§` 开头的是出处标签，用在「今天怎么看」「本站怎么看」；不以 `§` 开头的是原文定位，lint 核对它在那一段里。）
4. `先用中文过一遍：这一页的概念`：2–5 个 `<div class="concept" id="c-…">`，`<h3><span class="sec">§k</span>中文名 <span class="en">English</span></h3>`，正文不超过 320 个汉字（不算 SVG），最后 `<p class="use"><b>在这一页：</b>…</p>`（不超过 80 个汉字）。**从书外讲**：日常例子（秋千、自行车、电饭煲、手机充电器、家里的电表、Wi-Fi）、程序员熟的类比（但别硬套）、和容易混的概念分开（功 / 能量 / 功率，热 / 温度，电压 / 电流）。中文名用国内教科书的通行译法。概念归哪页讲见 `source/LINE.md`，别页讲过的用 `<a class="term" href="02.html#c-work">功</a>` 链过去。
5. `动手：模拟器`：见下「模拟器」。
6. `书里的人和项目`：一句 `.lede`（照抄样板），然后 3–8 个 `<h3><span class="sec">§k</span>标题</h3>` 小块，按在书里出现的顺序，每块不超过 260 个汉字（不算人物卡和图），尽量配图：
   - **人**：`.who` 人物卡（`<div class="who"><div><b>原名</b><span class="en">生卒年</span>一句话说是谁，在这一页里干什么。</div></div>`），一人一张；一笔带过的人不做卡片。代词：书里称 he / she 的历史人物可用他 / 她，其余用名字。
   - **项目和发明**：一座桥、一台机器、一次事故（谁、哪年、做了什么、为什么出名），讲到读懂这一节需要的程度。作者拿它说明什么，要在原文里有依据（「作者拿它来……」）。
   - **书里说的和史实有出入时**，按书写的写书里，史实另起一句说清；后来的事留给「今天怎么看」。
7. `原文里的词和句`：公共规范「英文伴读的词条」一节：8–20 条，按段号排，trap 至少三分之一，`.loc` 连续 4–7 个词。收：工程里的熟词生义（work、power、charge、stress、strain、field、load 的特定用法要讲清和日常义的差别）、英式说法和口语、作者的比喻、读者以后会在别处看到英文的说法。不收：四六级词汇、术语本身（放概念块）、专有名词。
8. `读完：作者到底说了什么`：3–5 条 `<div class="claim">`（`<h4>` 一句话的主张，`<p>` 凭什么，不超过 150 个汉字，`<span class="sec" data-p="段号…">§k</span>`，跨了几节就列几节），最后 `<p class="sowhat"><b>合起来：</b>…</p>`（不超过 120 个汉字）。拆页的章的后一页再加 `<p class="chapsum"><b>这一章合起来：</b>…</p>`（不超过 260 个汉字）。按主张之间的逻辑排，不按段落顺序；整节不超过 1100 个汉字。引用块（至多 2 处）放在这一节里，跟在它撑的那条主张后面：`<blockquote class="quote">英文<cite>— §2。本站译：中文</cite></blockquote>`。
9. `今天怎么看`：1–3 张卡，格式照样板（`<div class="today" data-verdict="…">`，`<h4>书里的说法：…</h4>`，`<dt>` 依次 书里 / 当时 / 今天 / 另一边（可省））。**「当时」是写书到 2012 年**，「今天」是 2012 年以后。结论四选一：成立 / 部分成立 / 被改写 / 有争议，判的是标题那**一句**。每个研究、数字联网核对，写明依据和 `<span class="asof">核对于 2026-11。依据：…</span>`；每张不超过 360 个汉字。
10. `本站怎么看`：2–3 块 `<div class="views">`（主流看法 / 作者的看法（标 `.at`）/ 本站的评论），每块不超过 420 个汉字，最后 `<p class="verdict"><b>本站的总体看法：</b>…</p>`（不超过 160 个汉字）。分工：「读完」只讲作者说了什么，「今天怎么看」只讲可检验的事实，评价都在这里。
11. `检查一下理解`：5–7 道 `<details class="check">`，`<textarea class="note" data-key="<页id>-oneline">`，`<div class="ponder"><p>想一想：…</p><textarea class="note" data-key="<页id>-ponder"></textarea></div>`。
12. `精彩回顾`：`<p class="recall-line"><b>一句话：</b>…</p>`，4–6 张 `<div class="item"><b>标题</b><p>…</p><span class="sec">§k</span></div>`。

## 模拟器

全书 6 个，一页至多一个（`need: ["sim"]`）。书里几乎没有算例，默认值多是常识定的演示值，**页面要说明哪些数是书里的、哪些是本站定的**。底稿 `source/line/NN.md` 的「模拟器候选」一节有脚本算好的数，照它复现。

| 页 | 模拟器 | 读者能做什么、默认设置要看到什么 |
|---|---|---|
| 02 | 推秋千（`#sim-02`） | 调推的间隔、推力、阻尼、链长；链长 2 米时固有周期约 2.84 秒，按周期推 30 秒振幅约 0.83 米，每 2 秒推一次只有约 0.11 米。阻尼调大能把振幅压下去（[3] 的桥）。**不拿它演示塔科马海峡大桥**（那是颤振，不是这种共振） |
| 03a | 卡诺上限（`#sim-03a`） | 调热端、冷端温度，看效率上限 1 − T冷/T热（开尔文），配热进 / 功出 / 热排的流向条；一个「直接用摄氏度算」的开关，看会错多少。书里只有定性结论，公式是本站补的 |
| 04a | 高压送电（`#sim-04a`） | 调送的功率、线路电阻，电压用书里出现过的档位（240 V 到 400 kV）；看线上电流、烧掉的功率、到用户手里的比例。电压升 3 倍，损耗变成约九分之一 |
| 05 | 蜂窝复用（`#sim-05`） | 调小区面积、可用频率数、复用分组数；书里的数是 800 个频率、每小区约 25 km²。小区从 25 km² 缩到 1 km²，全城同时通话多 25 倍，频率一个没加 |
| 06a | 安全系数和失效概率（`#sim-06a`） | 调安全系数（书里说 1.1–2）、材料强度和荷载的分散程度，看两条钟形曲线重叠多少。系数 2 但荷载很飘，可能比系数 1.5、荷载稳定的还危险。页面说明真实规范不是拿平均值相除 |
| 06b | 瑞士奶酪（`#sim-06b`） | 调防线道数、每道漏的概率、「坏日子」占比（组织有潜伏问题、好几道防线一起变差）。防线独立时加一道降十倍，有共同原因时只降一半左右。页面说明这是本站的简化模型，不是 Reason 给的公式 |

- 03b 不做模拟器：涡喷和涡扇的对比用一张自己画的静态图（底稿 03.md 的 03b「要的图」）。04b 的 LC 振荡在概念块里讲，说明它就是 02 那个秋千的电路版，链过去。

- 结构照样板：`<p>先猜：……</p>`（lint 查），`<div class="sim" id="sim-…">`（`.sim-head` / `.sim-body` 里 `.controls` `.stage` `.narrate` `.stats`），之后 `<ol class="qs">` 2–3 个「试试看」。一页两个模拟器时，每个之前各有一段「先猜」。
- 画曲线用共享脚本的 `EG.chart(el, { series, xlabel, ylabel, ymin, ymax, marks, hlines })`（用法写在 `assets/eg.js` 里它的注释），不要自己写画图代码。确定性，不用随机数（讲概率的模拟器除外，要给固定种子）。
- **用大白话写清每个控件和每个数字**。书里有算例的，默认设置复现它，在「试试看」里让读者对一下；照读者的顺序连着点一遍验过。
- 写 `tools/sim<页id>.mjs`（照样板页的）：用 playwright 照「试试看」连点，打印统计栏和说明，最后查没有 undefined / NaN。`check.mjs` 也会点所有按钮。
- 模拟器的目的是让读者先有直觉：「试试看」问看到了什么，不替作者下结论。

## 这本书特别要守的

- **不写成中文摘要。** 「通识读本」本身就是压缩过的，最容易被逐段转述。分节地图只说这一节干什么、留意什么；「读完」按主张之间的逻辑重组。
- **不复刻原书的 20 张图。** 要讲同一个原理（卡诺循环、发电机、晶体管电路、故障树），用自己的构图、标注和例子画。
- **物理要准，也别过度纠错。** 作者为了通俗会简化（「热就是能量」「电流像水流」）。页面讲概念时用教科书的说法；作者的简化会让读者记错的，在概念块里点一句「书里为了好懂说成……，严格说……」，不写成挑错清单。
- **几种声音分清**：Blockley 本人；他引的人（Petroski、Crawford、Popper、Rumsfeld……）；工程界和科学界的共识；本站。**他自己的框架**（五个「时代」、holon、对科学和工程关系的看法、对风险的看法）要标明是他的，不是通行分类。
- **说过头是最常见的错**：他常写 `often`、`can`、`may`、`most`、`I think`，页面不能写成「总是」「必然」「研究表明」。
- **英国背景要讲**：书里的职称（chartered、incorporated engineer）、英国的工程和事故、皇家学会和皇家工程院，读者不知道的一句话交代。
- **今天怎么看要具体**：书里点名的技术和工程后来怎样（摩尔定律、晶体管尺寸、电动车、可再生能源和电网、核电、AI 和自动化）；书里讲的风险观和后来的工程事故（事故名、年份、调查报告的结论）；工程教育和职业的变化。不让读者去看别的书。
- **数要对。** 概念块、模拟器、检查题里的每个数自己算一遍。
- **不写相对位置**（「上一节」「末尾」「前面说过」）：指路用 h2 的名字、§k，或原文 4–7 个词。lint 报的「？嫌疑」逐条在报告里答：改了，或者为什么不改。

## 图

- 文件名 `<页id>-小写英文名.jpg`，取图工具 `source/.venv/bin/python tools/fetch_img.py search|get`，一次一条命令。取图代理在你之前已经照底稿取好，清单在 `source/img/<页id>.md`，**照清单用，不自己找**；清单没有、你又非用不可的，在报告里说。
- 适合的照片：书里的真人（有自由授权肖像的工程师、科学家），工程和物件（桥、蒸汽机、发电机、早期晶体管、故障现场的公开照片），公有领域的历史版画和照片。新闻照片多有版权，不取。
- 适合自己画的：原理示意图（杠杆、滑轮、热机循环、发电机、晶体管开关、故障树）、时间线、因果链、「书里的说法 / 今天的数」对照。

## 搜索

WebSearch 额度是所有代理共用的，会中途用完；**grok 不用**。每页联网查证不超过 8 次，只查「今天怎么看」和书里、底稿里没有的事实；底稿已带出处的不重查。WebSearch 用不了时，用 web-fetch 代理直接读你知道网址的页面（英文维基、期刊论文页、IEA、IEEE、事故调查报告），再不行就列进报告的「拿不准」，**不写进页面**。

## 交稿前自检和报告

```sh
python3 -I tools/lint.py chapters/<页id>.html       # 必须 ✓；「？」开头的嫌疑在报告里逐条答
python3 -I tools/overlap.py chapters/<页id>.html    # 必须「全部通过」
node tools/check.mjs chapters/<页id>.html --shots source/shots/<页id>
node tools/sim<页id>.mjs                            # 模拟器页
```

报告在公共规范的底稿上加：

```
概念块：（id；链到别页的有哪些）
书里的人和项目：（几块；人物卡几张）
模拟器：（能调什么；默认设置下复现了书里哪些数；照读者顺序连着点验证过的「试试看」）
今天怎么看：每张卡的结论和依据网址
本站怎么看：几块看法，主流看法里点名的研究或人，各附一个出处网址
lint 的嫌疑：逐条，改了还是为什么不改
已核实的事实：（写进页面、拿得准的，附出处网址；审读不重查）
拿不准的事实：
```
