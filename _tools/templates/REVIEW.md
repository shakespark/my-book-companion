# 审读说明（模板）

写新书的 `source/REVIEW.md` 时照这份改：`<…>` 换成这本书的，没有译本、词条、模拟器或剧透要求的书删掉对应的条目，末尾「这本书的审读最常抓到的」从样板页的审读结果里填。
`source/` 不入库，所以这份模板放在 `_tools/templates/`。上一版是 `fooled/source/REVIEW.md`。

和上一版的差别（2026-11-15）：Fooled 的 131 处审读改动里，限定词和程度占 40 处，只有 4 处会让读者读歪；位置、节号 9 处，一处都不会。
所以**限定词只在方向或范围变了时才改，位置和节号交给 lint**。审读的力气花在事实、归属、词条、卡片、模拟器上：那几类 55 处里有 34 处会读歪。

**省额度**：每发一轮，整个上下文就要重读一遍。第一轮跑 `tools/pack.sh --review <ID>`（规范里和审读有关的几节、`source/LINE.md`、作者报告、这一页、这几节的原文和译本），第二轮在一条消息里并行 Read 清单上的全部文件；联网查询一次并行发出；改动攒齐了一轮改完。

用户说过审读「不必学术级」：只抓会让读者读歪的错。**一处改动要回答得了「不改，读者会对作者说了什么、或对某件事实形成错的印象吗」。回答不了就不改。**

## 查这几样

1. **方向和范围。** 页面上每一句「作者说」「书里说」，回 `data-p` 那一段：
   - 方向反了没有，意思变了没有；
   - 范围变了没有：只对一处的让步写成了整体，前提（「过了温饱线以后」这一类）丢了，原文没有的全称判断（都、只有、必然、从不、证明了）；
   - 「读完：作者到底说了什么」每条主张、「检查一下理解」每个答案，在原文找得到。

   **只差一档语气的不改**：原文 perhaps、often、seems，页面写「常常」「看来」「大概」或者干脆没写，而句子的方向和范围没变，就留着。不要为了补一个「也许」「几乎」去动页面。
2. **这句话是谁的。** 把本站的推论、作者转述的别人的话、书里人物的想法安到作者头上的，改掉。页面说「书里没给出处」「作者没说是谁」的，先查书后注释。
3. **事实。** 作者列为「拿不准」的，联网核；作者列为「已核实」、附了网址的**不重查**。金融、统计这类概念的方向（做多 / 做空、买方 / 卖方、中位数 / 平均数、概率 / 期望）要对。
4. **卡片**（今天怎么看、本站怎么看）：标题、标签、「今天」栏判的是不是同一句话；标题两件事并列而「今天」只判了一件的，把标题收窄成被判的那一件，标签跟着「今天」的最后一句走；有没有一边倒；「今天」只用出版以后的证据。**每张卡逐张看。**
5. **词条和译本勘误**（有的书才有）：词条的中文意思、「反话」「双关」「典故」的读法，回原文那一句看撑不撑得住。勘误：原文的意思本站说对了没有；译本真的错了、而且会让读者得出错结论吗；引的是不是那一句。译本措辞别扭但意思没错的，删掉这条。不必逐段通读译本找新错。
6. **模拟器**（有的页才有）：`node tools/sim<ID>.mjs`，照「试试看」的顺序点一遍，数字和说明对得上；书里的数在默认设置下复现得出来；模型的数学自己验算。
7. **剧透**（有的书才有）：以「还没读后面」的读者身份把读前部分读一遍，名单在 `source/LINE.md`。

改了一处，**全页搜同一个意思**再改（概念块、检查题、回顾里常留着旧说法）。

## 不做

- 措辞润色、换一种说法、补「更精确」但不算错的细节。
- 补限定词、调语气强弱（见第 1 条）。
- 位置词、节号标签、段号：lint 查。你顺手看到指错了、读者会因此找不到地方的，可以改。
- 重查已核实的事实。
- 改小节标题、`data-sec`、class 结构。

## 联网

先用 WebSearch（先调 `ToolSearch`，`query: "select:WebSearch"`）。搜索额度全会话共用，很紧；grok 搜索不要调。
每页最多搜 6 次，一次并行发出，只查「错了会让读者读歪」的。搜不了时不要等、不要绕；能直接打开的权威原页面可以用 curl 看一眼。查不到的改保守或删掉，在报告里写明。

## 改完

改前把原页存一份到你的 scratchpad（**系统提示里写着路径，用你自己会话的**）下 `review-<ID>/`。三项检查一条命令跑，都要过：

```sh
python3 -I tools/lint.py chapters/<ID>.html; python3 -I tools/overlap.py chapters/<ID>.html; node tools/check.mjs chapters/<ID>.html --shots source/shots/<ID>
```

不做 git 操作，不派子代理，不碰别的文件。

在 `source/reports/<ID>.md` 末尾加一节「## 审读（日期）」，不超过 25 行。**这一节在全部改完、三项检查都过之后一次写完**（主编的进度脚本看到「## 审读」就当你审完了，不要先写个标题再慢慢填）。**主编只读这一节来验收，所以每处改动要让他不打开页面也看得懂**：

- 第一行：改了几处，其中几处会读歪。
- 每处一行：在哪一节、原来怎么写、改成什么、依据（段号或网址）、类型（方向 / 范围 / 归属 / 事实 / 卡片 / 词条 / 勘误 / 模拟器 / 剧透），会读歪的标「★」。
- 查了没改、仍拿不准的；要主编定的事（跨页的、共享文件的）。
- 三项检查结果，联网几次。

最后一条消息只写一两句：改了几处、几处会读歪、三项检查过没过。
